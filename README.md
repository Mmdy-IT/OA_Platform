# 绵绵聚道 · OA 平台（一期 · 合同管理模块）

绵绵聚道内部 OA 平台一期，当前仅上线合同管理模块，聚焦「合同模板 → 业务填写 → 法务审核 → PDF 下载」的完整闭环；后续将按计划接入其他业务模块。

## 已实现功能

- 企业级工作台：面向全公司业务的统一 OA 门户，展示业务模块地图、快捷入口、个人组织信息和跨模块待办；合同管理作为已上线模块接入，其余业务模块按规划逐步扩展。
- 合同管理概览：原合同工作台迁移至「合同管理 → 合同概览」，集中展示合同统计、最近合同、待办和流程分布。
- 合同模板管理：法务/管理员可新增、编辑、预览、归档模板；已归档模板可永久删除。模板不再维护合同编码，合同编号统一从甲方主体读取。
- 模板导入：支持上传 Word（.docx）或 PDF 生成模板草稿，自动提取正文、表格和空白项，导入后可在编辑器中继续校对调整。
- 富文本模板编辑：支持字体、字号、加粗/斜体/下划线/删除线、颜色、对齐、行距、首行缩进、列表、引用、分隔线及表格编辑，排版效果同步到正式 PDF。
- 空白项配置：每个模板可配置独立字段，支持文本、多行文本、日期、数字、金额、下拉选（单选）和下拉选（多选）；多选内容在合同预览和 PDF 中自动以「、」分隔。新建空白项默认必填，可按需改为选填。
- 智能字段标识：新增空白项时，字段标识默认跟随显示名称自动生成；同一模板内自动去重，也可手动改写。
- 合同分类维护：模板编辑器中的分类支持下拉选择或直接输入新分类；新分类随模板保存写入数据库，并自动成为后续分类选项。合同创建时会把分类快照保存到合同记录和 `oa_contract_info.contract_category`。
- 中文占位符：正文可直接使用 `{{甲方}}`、`{{合同金额}}` 等中文占位符，字段标识同样支持中文，无需理解英文变量名；`{{合同编号}}` 为系统内置占位符，预览和正式 PDF 会自动填入生成的合同编号，无需配置空白项。
- 主体库联动：新增「甲方主体信息」「乙方主体信息」两个子模块。甲方主体维护主体编号，甲乙方主体均维护名称、统一社会信用代码、户名、开户行、行号、税号、联系地址和联系方式；业务起草合同时从 `mmdy_db.mmdy_party_info` 下拉选择主体，信用代码、地址、开户行等主体信息自动带出，联系人和联系方式由业务人员手动填写。
- 仓库信息联动：模板可把字段的数据来源设为仓库；业务起草合同时从 `mmdy_db.mmdy_warehouse_info` 下拉选择仓库简称，正文实际填充该仓库的完整地址。
- 自动版本号：模板创建固定为 `V1.0`，正文或空白项结构发生变化时自动升级小版本（如 `V1.1`、`V1.10`），仅调整名称等说明信息不升版本。
- 逐项填写要求：模板可设置通用填写要求，每个空白项可设置独立要求、占位提示和是否必填。
- 合同管理：业务人员可选择模板起草合同，保存草稿、修改已驳回合同、提交审核、撤回审核、删除草稿；合同列表只展示本人发起的合同，按每页 10 条分页。
- 合同附件：新建或编辑合同时可上传 Excel、Word、PDF 及图片附件，支持多文件、下载和删除；首次在新建页上传附件时会自动保存合同草稿。附件文件保存在 `data/attachments`，记录保存在 SQLite `contract_attachments` 表。
- 合同表格行调整：起草或修改合同时，可在不改动模板表头和列结构的前提下增删正文行；新增行为按表头命名的空白输入行，可逐列填写，并通过拖拽左侧行号图标调整行顺序。表格包含「序号」列时，序号会按数据行顺序自动生成并在增删、拖拽后重新排列；行内容与顺序随合同保存，并同步到详情预览与正式 PDF。
- 金额自动汇总：表格同时包含「数量」「单价」「总额（元）」列时，新增行会按「数量 × 单价」自动计算并锁定行总额；合同正文使用 `{{总额}}`、`{{总金额}}` 时，系统自动汇总「总额（元）」列中所有数据行（含新增行）并排除合计行；使用 `{{大写总额}}`、`{{总金额大写}}` 时，根据总额自动生成人民币大写金额。对于 `{{总费用大写}}`、`{{金额大写}}` 这类「对应小写字段 + 大写」的字段，也会根据小写金额自动生成中文大写。表格中的合计行会按所有明细行的「总额（元）」自动累加，并同步生成大写金额。模板正文可直接使用 `{{预付款}}`、`{{尾款}}`，系统按合同总额（优先取表格「总额（元）」合计，其次取总额/总费用/合同金额等字段）自动计算 30% 预付款与 70% 尾款，并以人民币大写展示；尾款按总额扣减预付款计算，确保两者合计与总额一致。汇总、预付款、尾款和大写字段均为只读，保存和 PDF 生成时会再次校验计算。
- 日期显示：日期字段在表单、合同预览和 PDF 中统一使用 `YYYY年MM月DD日` 格式。
- 法务审核：合同管理菜单下设有审核工作台，支持审核通过、驳回并填写意见、常用驳回意见快捷填入。
- 合同信息同步：保存草稿、提交审核、撤回、驳回和审核通过时，实时写入公司数据库 `mmdy_db.oa_contract_info`；记录合同名称、编号、编码、4 位流水号、草稿/待审核/已驳回/已通过状态、发起人及审批人等信息。
- 审核留痕：合同创建、修改、提交、重新提交、撤回、通过、驳回均写入流转记录。
- PDF 下载：仅审核通过的合同可下载中文正式 PDF，正文按 A4 分页，页脚仅保留居中页码。
- 合同包规则：管理员可为指定主合同模板绑定必须配套的「通用类」模板；新建主合同时只创建主合同记录，首次保存或提交时会检查通用合同是否存在，缺失则保存主合同、补建同编码通用合同并跳转填写。分类为「通用类」的模板不会出现在普通新建合同的可选模板中。
- 合同包命名与编号：配套通用合同在列表中显示为「主合同名称·通用合同名称」，与主合同共用主体编号，不在合同正文中显示独立合同编号。
- 菜单层级：侧边栏「合同管理」下统一收纳「合同列表」「甲方主体信息」「乙方主体信息」「审核工作台」「合同模板」「合同包规则」；菜单项按每个人员实际开通的子模块权限动态显示。
- 人员权限管理：管理员可从「系统管理 / 权限管理」查看全部人员，并逐人配置「工作台 / 合同列表 / 甲方主体信息 / 乙方主体信息 / 审核工作台 / 合同模板」子模块权限，同时维护飞书 `union_id` 绑定。权限数据保存在 `mmdy_db.oa_user_permission`。
- 权限申请：所有登录人员可在「系统管理 / 权限申请」选择需要开通的子模块并填写开通事由；所有系统管理员可审批，通过后自动合并到申请人的权限记录。申请记录保存在 `mmdy_db.oa_permission_request`。
- 权限隔离：合同列表始终只展示本人发起的合同；拥有「审核工作台」权限的人员仅可在审核工作台查看全部待审合同。合同、审核、模板等接口均按子模块权限校验，不只看角色。
- 合同删除：管理员和法务可在合同列表直接删除合同，删除前需二次确认；删除合同包内任一文件时会同时删除主合同和配套通用合同。
- 模板快照：合同创建时保存模板正文、字段结构和版本快照，后续模板修改不影响历史合同。

## 技术方案

- 后端：FastAPI + SQLite + ReportLab
- 前端：React 18 + TypeScript + Vite + Ant Design 5
- 鉴权：服务端会话、HttpOnly + SameSite Cookie、PBKDF2-SHA256 密码哈希
- 权限：`mmdy_db.oa_user_permission` 按人员保存子模块权限，接入飞书后使用 `union_id` 匹配身份
- 数据：默认保存在 `data/oa.db`，首次启动自动建表并写入演示数据

## 数据库配置

主体库、仓库库、合同归档表和人员权限表共用同一套 MySQL 连接配置，统一放在项目根目录的 `config.ini`：

```ini
[database]
host = your-mysql-host
port = 3306
user = your-mysql-user
password = your-mysql-password
name = mmdy_db

[tables]
party = mmdy_party_info
warehouse = mmdy_warehouse_info
contract_archive = oa_contract_info
user_permission = oa_user_permission
permission_request = oa_permission_request
```

首次部署可复制模板后修改：

```powershell
Copy-Item .\config.example.ini .\config.ini
```

`config.ini` 已被 `.gitignore` 忽略，不要提交真实数据库密码。服务器使用多版本发布目录时，可通过环境变量指定共享配置路径：

```powershell
$env:OA_CONFIG_FILE = "D:\OA_Platform\config.ini"
```

环境变量仍可覆盖配置文件，适合 NSSM 或临时排查：

```powershell
$env:OA_PARTY_DB_HOST = "your-mysql-host"
$env:OA_PARTY_DB_PORT = "3306"
$env:OA_PARTY_DB_USER = "your-mysql-user"
$env:OA_PARTY_DB_PASSWORD = "your-mysql-password"
$env:OA_PARTY_DB_NAME = "mmdy_db"
```

连接复用规则：

主体库不可用时，合同编辑页会自动降级为手工输入甲方/乙方名称，不影响合同继续起草。

仓库信息库不可用时，合同编辑页会降级为手工填写仓库简称和仓库地址，不影响合同继续起草。

合同归档表首次写入时会自动补充 `serial_no`、`contract_status` 等字段。

人员权限表首次打开「系统管理 / 权限管理」时会自动创建，并把 OA 本地人员同步进去。若 `mmdy_db` 暂时不可用，登录与合同功能会按角色默认权限降级运行，权限管理页面会提示数据库不可用。

人员角色以 `mmdy_db.oa_user_permission.role` 为唯一依据，本地 SQLite `users.role` 只用于初始化新人员，不会反向覆盖远程权限表。直接修改远程表后刷新页面即可生效；默认不缓存权限数据，如需降低远程查询频率，可通过 `OA_PERMISSION_CACHE_SECONDS` 设置缓存秒数。

表名也可以按需通过 `OA_PARTY_DB_TABLE`、`OA_WAREHOUSE_DB_TABLE`、`OA_CONTRACT_ARCHIVE_TABLE`、`OA_USER_PERMISSION_TABLE` 临时覆盖。

## 飞书登录

飞书 OAuth 配置位于 `config.ini` 的 `[feishu]` 段：

```ini
[feishu]
enabled = true
app_id = your-feishu-app-id
app_secret = your-feishu-app-secret
redirect_uri = http://your-oa-host:9650/api/auth/feishu/callback
auto_provision = true
```

登录页已改为飞书专用入口，不再提供账号密码登录。生产环境保持：

```ini
[auth]
password_login = false
```

顶部用户区显示飞书头像、姓名和 `oa_user_permission.job_title`；首次飞书登录会从 `mmdy_employee_info.job_title` 和 `dept_path` 同步岗位与部门，同时把飞书 `avatar_url` 写入 `oa_user_permission.avatar_url`。历史账号岗位为空时显示「岗位未设置」。

飞书开放平台需要配置：

- 网页应用主页：`http://your-oa-host:9650/feishu`
- 重定向 URL：`http://your-oa-host:9650/api/auth/feishu/callback`

登录流程：

1. 访问 `/api/auth/feishu/login`
2. 飞书授权后回调 `/api/auth/feishu/callback`
3. 后端使用 `union_id` 查询 `mmdy_db.oa_user_permission`
4. 已绑定账号沿用原角色和权限
5. 未绑定账号在 `auto_provision=true` 时自动创建普通账号，默认权限为「工作台 + 合同列表」
6. 登录成功后签发现有 `oa_session`，前端路由和权限体系无需改变

登录页会根据 `/api/auth/feishu/config` 自动显示「飞书账号登录」按钮。飞书客户端也可以把应用主页设为 `/feishu`，进入应用后自动发起授权。

前端开发模式（可选）：

```powershell
cd frontend
npm run dev
```

Vite 会把 `/api` 代理到 `http://127.0.0.1:8000`，因此后端仍需同时启动。

## 关键业务规则

- 只有草稿或已驳回合同可以修改，待审核和已通过合同内容锁定。
- 合同编号格式为「主体编号 + 年月日 8 位 + 4 位流水号」，例如 `CG202611250001`；主体编号在新建合同时根据所选甲方主体从 `mmdy_db.mmdy_party_info.party_no` 读取，流水号按「主体编号 + 自然日」从 `0001` 重新起算。甲方主体未配置主体编号时，系统会阻止保存并提示先维护甲方主体信息。
- `mmdy_party_info` 使用 `party_no` 字段保存主体编号；旧版本的 `contract_code` 列会自动重命名为 `party_no` 并保留原数据。已有甲方主体需要进入「甲方主体信息」编辑并补录主体编号后，才能按新规则创建合同。
- 合同信息在创建、保存、提交、撤回、驳回和审核通过时同步至 `mmdy_db.oa_contract_info`；`contract_status` 使用「草稿 / 待审核 / 已驳回 / 已通过」，`serial_no` 保存合同编号末 4 位流水号。同步失败时当前操作不会生效，避免 OA 与公司数据库状态不一致。
- 提交审核前会校验模板中全部必填空白项；合同包提交时会逐个检查包内所有合同，任一空白项未填写都不允许提交。
- 法务不能审核本人发起的合同。
- 驳回必须填写审核意见。
- 审核通过后才开放 PDF 下载；待审核阶段可在页面在线预览合同正文。
- 模板归档是日常下线方式：业务人员不再能选择该模板，但历史合同和模板快照不受影响。
- 仅已归档模板可永久删除：删除入口只对法务/管理员开放；删除后模板记录移除，历史合同保存的模板正文与字段快照保持不变。
- 子模块权限是接口与菜单的统一依据：新增账号首次登录时默认仅开通「工作台 + 合同列表」普通权限，法务、审核和模板等子模块须由管理员在权限管理中额外开通；已有权限配置不会被新账号默认值覆盖。管理员调整权限后，用户刷新页面或重新登录即可生效。
- 新增「甲方主体信息」权限后，原有管理员/法务账号需要由管理员在「系统管理 / 权限管理」中勾选该子模块，菜单才会显示。
- 飞书 `union_id` 允许留空，但同一 `union_id` 只能绑定一名人员；后续接入飞书登录时，将以该字段匹配 OA 人员及权限记录。
- 模板编辑器中甲方、乙方主体字段由系统自动生成，包括主体名称、统一社会信用代码、户名、开户行、行号、税号、地址、联系人和联系方式；其中主体名称、信用代码、地址、开户行等信息从主体库带出，联系人和联系方式为手动输入字段。总金额、总金额（大写）和签署日期也属于系统字段，系统字段不可删除或改写标识。
- Word/PDF 导入仅生成模板草稿：Word 中的图片、页眉页脚，以及 PDF 中的复杂表格/图形不会完整保留，导入后需人工核对提示信息并补齐正文与空白项。

## 部署注意事项

一期按单机内部系统实现。正式部署时建议补充：

- 接入飞书鉴权，并使用 `oa_user_permission.union_id` 匹配人员；同时移除演示账号。
- 使用 HTTPS，并设置 `OA_SECURE_COOKIE=true`。
- 将 SQLite 替换为 PostgreSQL/MySQL，或至少配置数据库文件定期备份。
- 增加 CSRF 防护、登录限流、密码修改与账号停用能力。
- 按公司制度接入电子签章、水印、合同编号规则和归档系统。
- PDF 中文渲染默认读取 Windows 的宋体、黑体、仿宋、楷体、微软雅黑字体；Linux 部署需安装对应中文字体，未匹配到的字体将回退到默认中文字体。
